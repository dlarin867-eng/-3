# Backend — ИИ-счётчик калорий для тренирующихся

Каркас блока 4 задачника (`../задачник.md`) — инфраструктура и база данных. Полная роль и стандарты работы — `.claude/agents/backend-developer.md`.

## Стек

Node.js + TypeScript, Fastify, PostgreSQL + Prisma, S3-совместимое хранилище фото (см. `.env.example`).

## Запуск локально

```bash
cp .env.example .env        # заполнить DATABASE_URL, JWT_SECRET минимум
npm install
npm run prisma:migrate      # создаёт таблицы по prisma/schema.prisma
npm run dev                 # http://localhost:3001
```

Проверить, что поднялось: `GET /health` и `GET /health/db`.

## Что уже есть (блок 4)

- Схема БД — 6 таблиц: `users`, `meals`, `meal_items`, `supplement_logs`, `daily_targets`, `weight_logs` (`prisma/schema.prisma`).
- Переменные окружения валидируются при старте (`src/config/env.ts`) — приложение не запустится с неполным `.env`, а не упадёт на первом запросе.
- Аутентификация: регистрация/логин (`POST /auth/register`, `/auth/login`), JWT, `requireAuth`-хук на защищённых роутах.
- Базовый роутинг: `/me`, `/meals`, `/weight`, `/supplements` — CRUD без внешних интеграций (ручной ввод работает уже сейчас).
- Хранилище фото (S3-совместимое, напр. Cloudflare R2) — загрузка/выдача подписанной ссылки/удаление, плюс запрос "что пора удалить по политике хранения" (`src/integrations/photo-storage.ts`).

## Блок 5 — интеграции

Claude API (распознавание блюда), Open Food Facts (штрихкод), USDA FoodData Central (сверка калорийности) — `src/integrations/`, подробности и что не протестировано вживую (нет реальных ключей) — там же README.md. Кэширование и обработка таймаутов/ошибок — `cache.ts`/`http-client.ts`.

## Блок 6 — бизнес-логика

Расчёт нормы, циклирование углеводов, автокоррекция по весу, тайминг напоминаний — `src/services/`, 4 файла, все — чистые функции, 29 юнит-тестов (`npm test`), подробности там же в README.md.

## Что ещё не здесь (сознательно — другие блоки)
