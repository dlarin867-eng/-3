# Интеграции — блок 5 задачника

- `http-client.ts` — fetch с таймаутом и одним повтором, единая `ExternalApiError` для отличения "внешний API недоступен" от прочих ошибок.
- `cache.ts` — in-memory TTL-кэш частых запросов к базам нутриентов (24ч) — без Redis на старте, интерфейс рассчитан на замену позже без изменения вызывающего кода.
- `open-food-facts.ts` — штрихкоды (ФТ-3.1-3.3), публичный API, живой сетевой запрос проверен вручную.
- `usda-fdc.ts` — сверка названия блюда с базой нутриентов (ФТ-2.5), требует `USDA_FDC_API_KEY`; без ключа просто не проставляет бейдж "сверено с базой", не ошибка.
- `claude-vision.ts` — распознавание блюда по фото через прямой Anthropic API со structured tool-use (ФТ-2.1-2.5), требует `ANTHROPIC_API_KEY`; активен при `AI_PROVIDER=anthropic`.
- `openrouter-vision.ts` — то же распознавание, но через OpenRouter (один ключ, много моделей/провайдеров, OpenAI-совместимый формат запроса) — JSON текстом вместо forced tool_choice, т.к. модель под капотом `openrouter/free` заранее не известна. Активен по умолчанию (`AI_PROVIDER=openrouter`).
- `meal-recognition.types.ts` — общий тип `RecognizedDish`, чтобы оба провайдера были взаимозаменяемы.
- `ai-vision.ts` — фасад: выбирает провайдера по `AI_PROVIDER`, вызывающий код (`api/routes/meals.ts`) импортирует только его.
- Оба провайдера: при таймауте (НФТ 5.1, 8с)/отсутствии ключа возвращают `null` — тот же путь, что и ручной ввод, не аварийная ошибка.
- `photo-storage.ts` — из блока 4, хранилище фото.

**`openrouter-vision.ts` протестирован вживую (2026-08-24)** — реальный ключ, реальное фото, см. `scripts/test-openrouter.ts` (сырой запрос) и `scripts/test-recognize-meal.ts` (сама функция `recognizeMealPhoto`). Механика подтверждена рабочей, но с оговоркой: **`OPENROUTER_MODEL="openrouter/free"` (роутер) на каждый запрос случайно выбирает одну из бесплатных моделей** — три живых прогона дали три разных результата: 3.8с с идеальным JSON, >60с без ответа (думающая модель не уложилась), 52.7с с синтаксически битым JSON (лишние кавычки) — даже с одной и той же моделью, закреплённой явно. `scripts/diag-openrouter-timing.ts` — вспомогательный скрипт для замера, оставлен для справки.

Это не баг кода: таймаут/битый JSON корректно уходят в `null` → тот же fallback, что и "ключ не настроен", роут оставляет запись черновиком под ручной ввод (НФТ 5.1). Осознанное решение фаундера (2026-08-24): пока остаёмся на бесплатном тире — годится, чтобы понять и проверить механику подключения (в т.ч. для будущего Telegram-бота на курсе), но **не годится как финальная проверка точности распознавания для блока 11** — для неё в будущем потребуется закрепить конкретную платную модель (пара центов за фото) вместо рандомного бесплатного роутера.

**Не протестировано вживую**: USDA FDC, `claude-vision.ts` (прямой Anthropic API — нет `ANTHROPIC_API_KEY`). Код написан по документации SDK/API и проходит типизацию, но не проверен реальным запросом.
