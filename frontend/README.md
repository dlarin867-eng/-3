# Frontend — ИИ-счётчик калорий для тренирующихся

Каркас блока 7 задачника (`../задачник.md`) — инициализация Next.js и дизайн-система в коде. Полная роль — `.claude/agents/frontend-developer.md`.

## Стек

Next.js (App Router) + TypeScript + React, без Tailwind — токены переносятся из `требования к дизайну.md` напрямую в CSS custom properties (`src/app/globals.css`), т.к. система уже полностью специфицирована и named-utility-подход Tailwind не добавляет ценности поверх готовых токенов.

## Запуск локально

```bash
npm install
npm run dev   # http://localhost:3000
npm run build # прод-сборка + проверка типов
```

## Что уже есть (блок 7)

- **Дизайн-токены** (`src/app/globals.css`) — цвета (тёмная тема основная, светлая через `prefers-color-scheme`/`data-theme`, три состояния theming как в артефактах-прототипах), типографика (Manrope/Inter через `next/font/google`), сетка/отступы/радиусы — один в один из `требования к дизайну.md` §2.
- **Компонентная библиотека** (`src/components/ui/`): `Button`, `Card`, `MacroRing` (единый узел для большого и малых колец КБЖУ), `DayPill`, `ConfidenceBadge`, `TabBar`, `ScreenHeader`.
- **Роутинг всех 9 экранов + онбординга**: `/onboarding`, `/main`, `/photo`, `/barcode`, `/sportpit`, `/diary`, `/weight`, `/reports`, `/settings`. 5 табов (`(tabs)` route group) под общим таб-баром, фото/штрихкод/спортпит — полноэкранные роуты с кнопкой «Назад».
- **`/main` собран по-настоящему** (не заглушка) — демонстрирует, что компоненты складываются в реальный экран: кольца КБЖУ, тоггл типа дня, быстрые действия.

## Блок 8 — экраны продукта

Все 9 экранов подключены к реальному backend API (`src/lib/api.ts` — тонкий fetch-клиент, JWT в localStorage; `src/lib/auth-context.tsx` — состояние пользователя).

- **Онбординг** (`/onboarding`) — полный квиз (§5.1), настоящий расчёт нормы через `POST /auth/register` → `GET /targets/today` (не имитация).
- **Главный** (`/main`) — реальная норма на сегодня, тоггл типа дня (`POST /targets/today/toggle-day-type`), блок "Ближайшее" (`GET /targets/today/upcoming`).
- **Фото** (`/photo`) — загрузка файла → `POST /meals/photo`, показывает либо распознанные позиции с `ConfidenceBadge`, либо честное "не удалось распознать — заполни вручную" (таймаут/нет ключа Claude — см. backend README).
- **Штрихкод** (`/barcode`) — ручной ввод номера (сканер камерой — не в этом блоке, см. ниже) → `POST /meals/barcode`, состояния "найдено"/"не найдено" по спецификации.
- **Спортпит** (`/sportpit`) — категория → количество порций → `POST /supplements`. Справочника позиций ≥50 с поиском в блоке 5/6 не было — статичный список категорий, отмечено в коде как открытый вопрос.
- **Дневник** (`/diary`) — `GET /meals`, автогруппировка по времени суток, удаление записи.
- **Вес** (`/weight`) — `GET/POST /weight`, карточка-предложение автокоррекции (`GET /weight/suggestion`, `POST /targets/today/apply-adjustment` — новый роут backend, добавлен в этом блоке, т.к. блок 6 умел только считать предложение, не применять).
- **Отчёты** (`/reports`) — недельный график по `GET /targets/history` (тоже новый роут backend), среднее по белку из дневника за 7 дней.
- **Настройки** (`/settings`) — профиль, тренировочные дни, тонкая настройка белка с подтверждающим диалогом выше 3,0 г/кг (`PATCH /me/protein-target`), переключатель темы, удаление аккаунта.

**Не реализовано сознательно** (за рамками блока 8): реальное сканирование штрихкода камерой (нужна отдельная библиотека), справочник спортпита с поиском на ≥50 позиций.
