## 1. Дизайн-система

### 1.1 Цветовая палитра

Принцип из agent2 п.1 и п.3.2: **dark-first как основная тема, полноценная light-тема — обязательна**, не опция. Обоснование дважды подтверждено: (а) исследование NN Group про контекстность предпочтений (тусклый свет вечером после тренировки → тёмная тема выигрывает; яркая кухня днём при фотографировании еды → светлая тема выигрывает — оба сценария у нас реальны и ежедневны); (б) WHOOP-паттерн «чёрный фон снижает усталость глаз рано утром/поздно вечером» — ровно наши пиковые сценарии использования (до/после тренировки).

**Тёмная тема (основная)**

| Роль | Hex | Применение |
|---|---|---|
| Фон (base) | `#121216` | Фон приложения, не чистый чёрный (Canvas Builder, agent2 п.4) |
| Поверхность (surface) | `#1B1B21` | Карточки, нижняя навигация |
| Поверхность приподнятая (elevated) | `#232329` | Модалки, bottom sheet, активные карточки |
| Граница (border) | `#2E2E36` | Разделители, обводки полей ввода |
| Текст основной | `#F5F5F7` | Заголовки, крупные цифры КБЖУ |
| Текст вторичный | `#9C9CA8` | Подписи, лейблы, второстепенные значения |
| Текст третичный/disabled | `#5C5C66` | Плейсхолдеры, неактивные элементы |

**Светлая тема**

| Роль | Hex | Применение |
|---|---|---|
| Фон (base) | `#FAF8F5` | Тёплый off-white, **не** `#FFFFFF` в лоб — иначе визуально сближается с «клинической» эстетикой Cronometer/MyFitnessPal (agent2 п.1, п.4), от которой сегмент осознанно отталкивается |
| Поверхность (surface) | `#FFFFFF` | Карточки на фоне off-white |
| Поверхность приподнятая | `#F2EFEA` | Модалки, hover-состояния |
| Граница | `#E4E0D8` | Разделители, поля ввода |
| Текст основной | `#1C1C1F` | Заголовки, крупные цифры |
| Текст вторичный | `#6B6B75` | Подписи |
| Текст третичный/disabled | `#A6A6AD` | Плейсхолдеры |

**Акцентные и семантические цвета** (одинаковые роли в обеих темах, с раздельной калибровкой контраста)

| Роль | Dark | Light | Обоснование |
|---|---|---|---|
| Брендовый акцент / основной CTA | `#FF6A3D` | `#E2531F` (затемнён для контраста на белом) | Тёплый оранжево-амбер, не зелёный — зелёный «занят» категорией (Cal AI, Foodvisor: цвет = «качество еды»); оранжевый — цвет, выигравший сравнение UX Collective для главной CTA-кнопки Cronometer (agent2 п.4) |
| Тренировочный день | `#FF6A3D` (= брендовый акцент) | `#E2531F` | Совпадение с брендовым акцентом намеренно: «тренировочный день» = высокая энергия = тот же цвет, что и основной CTA продукта. Усиливает связку «наша фича = наш бренд» |
| День отдыха | `#5B84D9` | `#3D63B8` | Холодный синий, пара к оранжевому — принцип WHOOP «цвет = устойчивый смысл», перенесённый на **нашу** ключевую ось (тип дня), не на recovery-метрики WHOOP (agent2 п.1, п.3.2) |
| Белок (протеиновое кольцо) | `#3DBD8C` | `#268F65` | **Отдельный, третий цвет, не зависящий от типа дня.** Прямое визуальное следствие ФТ-4.3 («норма белка должна оставаться постоянной вне зависимости от типа дня») — белок единственный макрос с фиксированным цветом, калории/углеводы перекрашиваются оранжевый↔синий по типу дня, белок — всегда зелёно-бирюзовый. Это не декоративный выбор, а прямое кодирование бизнес-правила в цвет |
| Низкий confidence (ФТ-2.4) | `#E0B929` | `#A87E12` | Приглушённый жёлтый, **намеренно другой оттенок**, чем брендовый оранжевый — предотвращает путаницу «это призыв к действию» vs «это требует проверки» (явная рекомендация agent2 п.4, последний абзац) |
| Успех / цель достигнута | `#4CAF6D` | `#2E8B4F` | Чекмарки, «норма выполнена», сверка с базой нутриентов подтверждена |
| Ошибка / удаление | `#E5484D` | `#C6333B` | Деструктивные действия, отклонённая корректировка нормы |

Контраст текст/фон проверен на соответствие WCAG AA (подробнее — раздел 6).

### 1.2 Типографика

**UI/тело текста: Inter.** Обоснование из agent2 п.4: де-факто стандарт с отличной кириллицей (критично — интерфейс только на русском, [[техзадание]] разд. 13), нейтральный характер не отвлекает от данных на data-dense экранах (главный экран, дневник, отчёты).

**Display/крупные цифры КБЖУ: Manrope.** Обоснование: agent2 явно предостерегает от Oswald/Barlow Condensed как «типового fitness-шаблона», уже примелькавшегося в нише (используется массово, снижает узнаваемость). Manrope — геометричный, спортивный характер, полная кириллица, доступен бесплатно — даёт ощущение «архитектурности» уровня MacroFactor/Pentagram без бюджета на кастомный шрифт (agent2 п.4, прямая цитата обоснования). Golos Text — резервный вариант с тем же обоснованием (сильная изначальная кириллица), если Manrope не даст нужного начертания при тестировании на реальных цифрах.

**Шкала размеров** (mobile-first, базовая единица 4px):

| Токен | Размер / line-height | Шрифт/начертание | Применение |
|---|---|---|---|
| `display-xl` | 56px / 60px, Bold | Manrope | Главное число «ккал осталось» на главном экране |
| `display-l` | 40px / 44px, Bold | Manrope | Числа Б/Ж/У под кольцами, вес тела на графике |
| `display-m` | 28px / 32px, SemiBold | Manrope | Итоги за приём пищи, число на карточке блюда |
| `heading-l` | 22px / 28px, SemiBold | Inter | Заголовки экранов |
| `heading-m` | 18px / 24px, SemiBold | Inter | Заголовки секций/карточек |
| `body` | 16px / 24px, Regular | Inter | Основной текст, поля ввода (16px — жёсткий минимум, меньший размер триггерит авто-zoom при фокусе на iOS Safari) |
| `body-s` | 14px / 20px, Regular | Inter | Вторичные подписи, лейблы под цифрами |
| `caption` | 12px / 16px, Medium, uppercase, +2% letter-spacing | Inter | Теги типа дня, confidence-лейблы, единицы измерения |

Прямое противодействие жалобе «tiny macro numbers» на редизайн MyFitnessPal (agent2 п.5, пункт 3): `display-xl`/`display-l` — обязательный минимум для чисел КБЖУ на главном экране и карточке блюда, не опускать до `body` даже в компактных карточках дневника (там — минимум `display-m`).

### 1.3 Сетка и отступы

- Базовая единица отступа: **8px** (кратно 4px для мелких внутренних отступов иконок).
- Мобильный контейнер: боковые поля **16px**, ширина viewport 360–428px — целевой диапазон разработки.
- Планшет/десктоп (веб-приложение открывают и с ноутбука): контент центрируется, `max-width: 480px` для колоночных экранов (главный, дневник, отчёты) — приложение сознательно не «растягивается» в широкий десктоп-лейаут, а остаётся мобильным столбцом с более широкими полями фона, чтобы сохранить оптимизированную для одной руки плотность данных.
- Вертикальный ритм секций: 24px между смысловыми блоками, 12px между связанными элементами внутри блока (например, кольцо КБЖУ и подпись под ним).
- Нижняя таб-навигация: фиксированная высота 64px + safe-area-inset для мобильных браузеров.

### 1.4 Скругления

| Токен | Радиус | Применение |
|---|---|---|
| `radius-s` | 8px | Чипы, бейджи, поля ввода |
| `radius-m` | 12px | Кнопки |
| `radius-l` | 16px | Карточки (блюдо, продукт спортпита, элемент дневника) |
| `radius-xl` | 24px | Bottom sheet (верхние углы), модальные окна |
| `radius-full` | 999px | Пилюли (тег типа дня, confidence-бейдж), круглые кнопки (камера) |

### 1.5 Иконография

Стиль: **outline, 24×24px сетка, толщина обводки 1.5–2px, скруглённые концы** — набор **Lucide** (открытый, нейтральная геометрия, согласуется с Inter, покрывает весь нужный набор: камера, штрихкод, весы, колба/капсула для спортпита, пламя/луна для типа дня). Заполненные (filled) версии иконок используются только для активного состояния таб-бара — эта пара filled/outline становится единственным индикатором «текущий раздел» вместе с цветом акцента.

Специфичные пиктограммы, которые нужно либо взять из набора, либо доработать вручную: пламя (тренировочный день), полумесяц/лист (день отдыха), мерная ложка (протеин), капсула (BCAA/предтреник), таблетка (креатин), весы (взвешивание), штрихкод, галочка-щит («сверено с базой нутриентов», ФТ-2.5).

## 2. Компонентная библиотека

### 2.1 Карточка распознанного блюда (ФТ-2.2–2.5)

Назначение: черновик после фото/штрихкода, редактируемый до подтверждения (ФТ-2.3).

**Структура (сверху вниз/слева направо):**
- Миниатюра фото блюда (56×56px, `radius-m`) слева.
- Поверх миниатюры, в правом верхнем углу — **confidence-индикатор**: цветная точка-кольцо (`#4CAF6D` высокий / `#E0B929` низкий, см. 1.1) + при низком confidence текстовый caption-бейдж «проверьте вес» на самой карточке, а не только цвет (см. раздел 6 — цвет не единственный носитель информации).
- Название блюда — `body`, редактируется по тапу (инлайн-редактирование, не отдельный экран — минимизирует трение согласно НФТ «<15 секунд на приём пищи»).
- Вес порции — `body-s`, редактируется степпером (±10 г тап, long-press — быстрая прокрутка) или свайпом по числу.
- Четыре мелких стата КБЖУ в ряд под названием: `ккал / Б / Ж / У`, `body-s` цифры, `caption` подписи.
- Если название совпало с базой нутриентов (ФТ-2.5) — маленький бейдж-щит «сверено с базой» зелёного `#4CAF6D`, поясняет пользователю, почему цифры внезапно «точнее», чем обычная ИИ-оценка.
- Правый край: иконка-карандаш (полный экран редактирования — вес/название/фото повторно) и иконка-крестик (удалить позицию из черновика).
- В самом низу карточки-контейнера (если распознано несколько блюд на фото) — общая сумма КБЖУ и кнопка **«Подтвердить»** (`radius-m`, брендовый акцент, полная ширина, высота 52px — попадает в основной сценарий использования одной рукой).

**Состояние низкого confidence:** обводка карточки 1.5px `#E0B929` вместо стандартной `#2E2E36`/`#E4E0D8`, лёгкий тонированный фон (5% непрозрачности жёлтого поверх surface) — отличие заметно даже при беглом взгляде, не требует чтения текста.

### 2.2 Индикатор дневной нормы КБЖУ (ФТ-4.4)

Реализует «уровень 1» прогрессивного раскрытия данных (agent2 п.3.1: три числа для мгновенного решения).

**Структура:**
- Верхняя строка: **пилюля типа дня** — `radius-full`, заливка цветом типа дня (оранжевый/синий), иконка (пламя/полумесяц) + текст «Тренировочный день» / «День отдыха», `caption` uppercase. Обязательно на первом экране (прямое требование ФТ-4.4 и явная рекомендация agent2 п.3.3 — не прятать в настройках, как это сделал Strongr Fastr).
- Центр: одно большое кольцо (донат, толщина обводки 12px) — калории, `display-xl` число внутри («Осталось: 1 240 ккал»), цвет заливки прогресса = цвет типа дня (оранжевый/синий — калории и связанные с ними углеводы цикличны по дню, см. 1.1).
- Под кольцом — три маленьких кольца в ряд (диаметр ~72px каждое) для Б/Ж/У:
  - Белок — **всегда** зелёно-бирюзовый `#3DBD8C`, независимо от типа дня (визуализация ФТ-4.3).
  - Углеводы — цвет типа дня (оранжевый/синий), синхронно с большим кольцом калорий.
  - Жиры — нейтральный серо-фиолетовый `#8B85A6`/`#6E6885`, не участвует в цветовой оси типа дня.
- Под каждым малым кольцом — `display-m` число «осталось» + `body-s` «из XXX г».
- Нижняя строка (опционально, свёрнута по умолчанию, разворачивается тапом) — сравнение с предыдущим типом дня: «вчера (отдых): 210 г углеводов → сегодня (тренировка): 380 г» — переносит принцип agent2 п.3.2 «выучил цвет один раз — применяешь везде» в конкретику интерфейса.

### 2.3 Быстрый ввод спортпита (ФТ-6.1–6.4)

Отдельная категория, визуально и навигационно не смешанная с общей едой (прямое требование ФТ-6.1 и предостережение agent2 п.5.7 против «размывания путей ввода еды»).

**Экран/шторка:**
- Сетка 2×3 крупных иконок-категорий (протеин, гейнер, креатин, BCAA, предтреник, «другое»), каждая — `radius-l`, 44%×88px, с подписью под иконкой.
- Тап по категории → список позиций из справочника (поиск сверху, `body` инпут), сортировка по частоте использования пользователем.
- Элемент списка: название бренда/продукта, единица порции уже проставлена по умолчанию из справочника («1 мерная ложка» / «1 капсула» / «1 таблетка» — ФТ-6.2, без взвешивания), степпер количества порций, КБЖУ на порцию мелким `caption`.
- Кнопка **«Добавить»** справа от элемента — фиксирует запись сразу, без промежуточного экрана подтверждения. Это даёт ровно **2 тапа** (категория → добавить), что соответствует критерию приёмки Фазы 2 из [[техзадание]] («залогировать спортпит за 2 действия»).
- **Креатин — отдельная логика** (ФТ-6.4): в карточке категории «Креатин» вместо обычного счётчика порций — переключатель-привычка («Принято сегодня» / чекбокс с полосой streak за 7 дней), визуально отделён от КБЖУ-логирования тонкой границей и подписью «это не влияет на подсчёт калорий» — предотвращает путаницу пользователя.

### 2.4 Экран сканирования штрихкода (ФТ-3.1–3.3)

- Полноэкранный видоискатель камеры (`getUserMedia`), затемнённая маска сверху/снизу, светлая рамка-гид по центру (`radius-m`, ширина ~80% экрана, высота ~30%) — фокусная зона для штрихкода.
- Автодетект: как только штрихкод распознан — рамка мгновенно становится зелёной (`#4CAF6D`) + вибро-отклик (Vibration API, если доступен) + короткая анимация схлопывания рамки в точку.
- Нижняя панель: переключатель фонарика (иконка), кнопка «Ввести вручную» (fallback, всегда видима, не только при ошибке).
- Успех (ФТ-3.2): bottom sheet снизу вверх — фото упаковки (если есть в Open Food Facts), название, КБЖУ на 100 г, степпер порции/веса, кнопка «Добавить в дневник».
- Не найдено (ФТ-3.3): та же bottom sheet, состояние-заглушка «Продукт не найден в базе» + кнопка «Создать вручную» → форма (название, КБЖУ на 100 г) с пометкой «сохранится для будущих сканирований».

### 2.5 График динамики веса (ФТ-8.2, автокоррекция ФТ-7.2–7.4)

Прямое применение вывода agent2 п.3.4 (MacroFactor): показывать **сглаженный тренд**, а не только «шумные» ежедневные точки.

- Линейный график: полупрозрачные точки фактического веса (низкая непрозрачность, `#9C9CA8`/`#6B6B75`) + сплошная жирная линия тренда поверх (цвет — брендовый акцент или нейтральный тёмно-синий, не завязан на тип дня — вес не цикличен по тренировочным дням).
- Переключатель диапазона сверху: 2 недели / месяц / 3 месяца (`caption`-таблы, `radius-full`).
- Точки-аннотации на графике в местах, где сработала автокоррекция нормы (ФТ-7.3) — маленький маркер с всплывающей подписью по тапу: «Норма изменена: 2 400 → 2 550 ккал» (тот же язык, что в user-сценарии [[идея]] п.3: «твой вес стабилен третью неделю... добавляю +150 ккал»).
- Карточка-предложение корректировки (когда доступна, ФТ-7.3–7.4): отдельная плашка над графиком, не модальное окно, — заголовок «Пора скорректировать норму», текст-обоснование в разговорном тоне, две кнопки на всю ширину: «Принять» (акцент) / «Отклонить» (нейтральная, outline). Плашка не блокирует остальной интерфейс — соответствует некритичности действия по НФТ.
- FAB (плавающая кнопка) внизу справа — быстрый ввод веса, открывает минимальную шторку с одним числовым полем и клавиатурой, автофокус, без лишних полей (частота ввода — раз в 2–3 дня по ФТ-7.2, трение должно быть минимальным).

### 2.6 Вечерняя сводка «не хватает N г белка» (ФТ-5.4)

- Формат: карточка/пуш-уведомление, при открытии — модальное полноэкранное состояние или отдельная шторка (не встраивается молча в общий фид, чтобы не потеряться).
- Заголовок `heading-m`: «Сегодня не хватает 38 г белка» — число белка крупнее остального текста в заголовке (`display-m` инлайн).
- Под заголовком — компактная копия протеинового кольца (зелёный, всегда тот же цвет что на главном экране — консистентность считывания).
- Три карточки-варианта продукта в горизонтальном скролле (яйца, творог, протеиновый коктейль — конкретные примеры из [[идея]] п.2.3): иконка/фото, название, «+24 г белка», кнопка «Добавить» прямо на карточке — одно касание логирует продукт без перехода на другой экран.
- Внизу — ненавязчивая ссылка «Настроить время сводки» (по умолчанию 20:00, ФТ-5.4, настраивается) и кнопка «Скрыть на сегодня».

## 3. Дизайн экранов MVP (9 экранов, [[техзадание]] разд. 9)

Везде: mobile-first, основной брейкпоинт 360–428px; на более широких вьюпортах — центрированная колонка `max-width: 480px` (см. 1.3).

### Экран 1 — Онбординг (цель, параметры тела, тренировочные дни)

Реализован как **quiz-flow**, детально расписан в разделе 4. Здесь — сводно по итоговому состоянию: экран не единый длинный список полей, а последовательность из ~9–10 отдельных шагов с прогресс-баром сверху (тонкая полоса, `radius-full`, заполняется брендовым акцентом). Кнопка «Далее» — full-width, фиксирована снизу, появляется активной только после валидного ответа на текущий шаг. Кнопка «Назад» — иконка-стрелка в левом верхнем углу, не текстом (экономия места на маленьких экранах).

### Экран 2 — Главный экран

Приоритет информации (сверху вниз, по убыванию важности — прямое следствие agent2 п.3.1, «уровень 1» не мешать с «уровнем 2»):

1. Шапка: дата + пилюля типа дня (компонент 2.2) — первое, что видит пользователь, до чисел.
2. Кольца КБЖУ (компонент 2.2) — центральный элемент экрана, занимает ~40% высоты первого экрана без скролла.
3. Горизонтальный ряд быстрых действий (3 крупные кнопки-иконки: «Фото», «Штрихкод», «Спортпит») — иконка + подпись, 88×64px каждая, единая раскладка равными долями ширины, четвёртая точка входа намеренно не добавляется (agent2 п.5.7).
4. Блок «Ближайшее» — контекстные подсказки по таймингу (ФТ-5.2–5.3): если до тренировки <2 часов и последний приём пищи низкоуглеводный — карточка-предупреждение; если после тренировки <2 часов — карточка-напоминание о белке. Показывается только при выполнении условия, не занимает место в остальное время.
5. Ниже линии скролла — последние 2–3 записи дневника за сегодня (превью, тап → полный экран дневника).

Мобильное поведение: кольца и быстрые действия — всегда в зоне видимости без скролла на экране 375×667px и выше; контекстный блок и превью дневника уходят под скролл первыми.

### Экран 3 — Съёмка/загрузка фото → карточка распознанных блюд

- Съёмка: полноэкранный видоискатель камеры, крупная круглая кнопка спуска затвора (72px, `radius-full`, брендовый акцент, нижний центр — попадает в зону большого пальца) + миниатюра галереи слева от неё (алтернатива — загрузка файла) + переключатель фронтальной/тыловой камеры справа.
- После съёмки — состояние загрузки: скелетон-карточка с анимацией пульсации + текст «Распознаём блюдо...» (не более 8 секунд по НФТ 5.1, если дольше — таймаут с fallback на ручной ввод).
- Результат — одна или несколько карточек блюда (компонент 2.1) вертикальным списком, редактируемых инлайн.
- Кнопка «Подтвердить всё» снизу — полная ширина, дизейблится, пока хотя бы одна карточка имеет незаполненное обязательное поле (вес = 0).

### Экран 4 — Сканирование штрихкода

Описан как компонент 2.4. На уровне экрана — отдельный пункт в быстрых действиях главного экрана (а не вложен в экран фото), несмотря на то что оба ведут в дневник — разведение путей ввода по назначению (agent2 п.5.7): фото — для нерасфасованной еды, штрихкод — для упаковки.

### Экран 5 — «Спортпит»

Описан как компонент 2.3. Отдельный таб-раздел (не подпункт настроек или дневника) — соответствует прямому предупреждению agent2 п.5.6 против «зарывания» ключевой фичи. Верх экрана — блок креатин-привычки (streak-полоска за 7 дней), если у пользователя отмечен приём креатина как регулярный — это первое, что видно, до сетки категорий, закрепляя привычечный, не КБЖУ-характер этого элемента.

### Экран 6 — Дневник (список записей за день/период)

- Переключатель день/неделя сверху (табы, `radius-full`).
- Список записей группирован по приёмам пищи (завтрак/обед/ужин/перекус/спортпит — автоматическая группировка по времени суток), заголовок группы — `heading-m` + сумма ккал группы.
- Элемент списка: миниатюра (если есть фото) слева 40×40px, название + вес `body`, КБЖУ компактно `body-s` справа, свайп влево — быстрое удаление, тап — открывает карточку блюда (компонент 2.1) для правки.
- Записи спортпита визуально отличаются: без фото-миниатюры, вместо неё — иконка категории на цветной подложке (нейтральный фиолетово-серый фон, не бренд-оранжевый — спортпит не участвует в цветовой оси типа дня).
- Записи с низким confidence сохраняют жёлтую индикацию (1.1) даже в списке дневника — консистентность считывания через весь путь пользователя, не только на экране распознавания.

### Экран 7 — Вес тела (ввод + график)

Описан как компонент 2.5. Верх экрана — крупное текущее значение (`display-xl`) + дельта за 7 дней (`body`, со знаком + / − и цветом успех/нейтральный в зависимости от совпадения с целью — набор массы: рост веса зелёный; сушка: снижение веса зелёный). График — ниже, занимает основную область экрана.

### Экран 8 — Отчёты (недельная сводка)

Реализует «уровень 2» прогрессивного раскрытия (agent2 п.3.1):
- Верх: график калорий за 7 дней, столбцы, цвет каждого столбца = цвет типа дня того дня (оранжевый/синий) — недельный график становится читаемым «на глаз» без подписей: чередование цвета = чередование тренировочных дней и дней отдыха, визуализация самого УТП продукта.
- Под графиком: среднее по белку за неделю (`display-l`) с индикатором «в норме / ниже целевого» (сравнение со средним таргетом).
- Блок «Точность» (не MVP, задел на Фазу 3 — но место в сетке зарезервировать): доля подтверждённых без правок распознаваний за неделю — метрика из [[техзадание]] разд. 11, полезно показать и пользователю, не только в аналитике продукта.

### Экран 9 — Настройки профиля и цели

- Секции: «Профиль» (пол, возраст, рост, текущий вес), «Цель» (набор/сушка/поддержание — выбор карточками, не выпадающим списком, тот же визуальный формат, что на онбординге, для консистентности), «Тренировочные дни» (недельная сетка 7 переключаемых дней, дни подсвечиваются цветом типа дня при включении — мгновенный визуальный фидбэк), «Спортивное питание» (управление избранными продуктами справочника), «Уведомления» (время вечерней сводки, тайминг вокруг тренировки), «Приватность» (удаление аккаунта — ФТ, разд. 5.3), «Тема» (авто/светлая/тёмная).
- Изменение цели/тренировочных дней (ФТ-1.3) отражается сразу — на выходе из экрана показывается короткий тост «Норма пересчитана» со ссылкой «Посмотреть» → главный экран.

## 4. Онбординг-флоу как quiz

Прямое применение agent2 п.2.1: quiz-to-paywall работает (Noom >10% конверсии vs медианных 2.7%), оптимальная длина воронки 3–5 экранов до paywall, и — что критично для нас — **каждый вопрос реально управляет формулой расчёта нормы** (ФТ-1.1–1.2), а не декоративен. Это отличает наш случай от 86%-раздражения, которое вызывают «prompts ни на что не влияющие» (agent2 п.2.1, п.5.4).

Общее число содержательных шагов — **9**, что попадает в диапазон, ближе к верхней границе рекомендованных 3–5 «до paywall», но у нас после квиза следует не paywall, а **расчёт и показ ценности** (бесплатный базовый функционал доступен сразу, платный слой — адаптивный, см. [[идея]] разд. 6) — поэтому длина квиза оправдана точностью формулы, а не воронкой продаж; сам paywall/trial-момент — на стыке с лендингом, координируется с агентом 4.

**Порядок экранов:**

1. **Приветствие/позиционирование.** Один экран, короткий заголовок + один визуал (например уже спроектированное кольцо КБЖУ типа дня, agent2 п.2.4 — «product-forward», не абстрактная иллюстрация даже здесь). Кнопка «Начать».
2. **Пол.** Два больших тап-таргета (карточки, не радио-кнопки) — влияет на формулу Миффлина-Сан Жеора (ФТ-1.2).
3. **Возраст.** Числовой степпер/колесо прокрутки, крупные цифры (`display-l`) — влияет на формулу.
4. **Рост и текущий вес.** Один экран, два поля рядом (переключатель см/футы, кг/фунты) — влияет на формулу и на будущие расчёты г/кг белка (ФТ-1.4).
5. **Цель.** Три карточки на всю ширину, вертикально: «Набор массы» / «Поддержание» / «Сушка» — с однострочным пояснением под каждой («увеличение калорий» / «текущий вес» / «снижение веса, сохранение мышц»). Прямое влияние на диапазон г/кг белка (ФТ-1.4) и % от поддержания ([[идея]] таблица п.2.1).
6. **Уровень активности.** 4–5 карточек (сидячий/лёгкая активность/умеренная/высокая/очень высокая) с однострочными примерами — множитель формулы Миффлина-Сан Жеора.
7. **Тренировочные дни.** Недельная сетка 7 тапаемых дней (Пн–Вс), выбранные дни подсвечиваются брендовым/тренировочным оранжевым сразу при тапе — первый момент в продукте, где пользователь **видит** цветовую пару тип-дня в действии, до того как она появится на главном экране. Прямое влияние на ФТ-4.1–4.2.
8. **(опционально) Время тренировки.** Если пользователь отметил ≥1 тренировочный день — короткий доп. шаг: «Во сколько обычно тренируешься?» (тайм-пикер), явно помечен как «можно пропустить» — влияет на ФТ-5.1–5.3, но не блокирует прохождение, если пользователь пока не готов ответить.
9. **Загрузка/расчёт.** Экран-мост между вопросами и результатом: анимация (пульсирующие кольца КБЖУ, набирающие значение) + текст **«Считаем твою тренировочную норму КБЖУ...»** — прямое применение приёма Adapty (agent2 п.2.1) с нашим честным отличием: расчёт **действительно** происходит здесь (формула на основе ответов 2–8), а не имитация. Длительность 2–3 секунды, не дольше — не злоупотреблять паттерном.
10. **Результат.** Показ рассчитанной нормы сразу в формате главного экрана (компонент 2.2) — с явной подписью-мостиком «На основе твоих ответов — вот твоя норма на сегодня» (прямая рекомендация agent2 п.2.1 — явно показать пользователю связь ответов и результата, чтобы усилить ощущение неслучайности вопросов). Показываются оба состояния переключением-подсказкой: «Так будет выглядеть тренировочный день / день отдыха» — двойной первый контакт с УТП продукта. Кнопка «Начать пользоваться» ведёт в приложение (в бесплатном тарифе); отдельный, не блокирующий баннер про платный адаптивный слой — вне рамок этого документа (см. координацию с агентом 4 и [[идея]] разд. 6 — freemium, не hard paywall, согласно agent2 п.2.2).

**Технические поля ФТ-1.4** (белок 1,4–2,0 / 2,3–3,1 г/кг, значения >3,0 г/кг с предупреждением, НФТ 5.4) реализуются не отдельным шагом квиза, а автоматическим расчётом на основе шага 5 (цель) с возможностью ручной тонкой настройки позже в Настройках (экран 9) — квиз не перегружается специализированным вопросом, который 95% пользователей не смогут содержательно заполнить сходу.

## 5. Паттерны обратной связи и микровзаимодействий

### 5.1 Визуализация confidence ИИ-оценки

- Три уровня из ФТ-2.2 (`confidence: high/medium/low`) кодируются **и цветом, и текстом, и иконкой** одновременно (не только цветом — см. раздел 6, доступность):
  - High — без специальной обводки, маленькая серая галочка-иконка, без текста (не отвлекает — это ожидаемое состояние).
  - Medium — тонкая жёлтая обводка карточки (1px), без блокирующего текста, но при разворачивании карточки — подсказка `caption`: «оценка приблизительная».
  - Low — обводка 1.5px `#E0B929`, тонированный фон карточки, явный текстовый бейдж «Проверьте вес» на самой карточке (не требует разворачивания), иконка предупреждения.
- Анимация появления карточки блюда после распознавания: fade-in + едва заметный slide-up (150мс), при low confidence — дополнительно однократный лёгкий «пульс» обводки (200мс), привлекающий внимание без раздражения (не повторяющаяся анимация).

### 5.2 Правка распознанного блюда

- Тап на название/вес → инлайн-переход поля в режим редактирования (не модальное окно) — минимизация трения, поле подсвечивается брендовым акцентом по фокусу, клавиатура выезжает снизу.
- Изменение веса степпером/слайдером → КБЖУ-цифры на карточке **пересчитываются в реальном времени** с коротким flip/count-анимация чисел (не мгновенная подмена — 200–300мс тикер, чтобы пользователь видел, что именно изменилось и в какую сторону).
- После ручной правки — confidence-индикатор карточки автоматически переключается в состояние «подтверждено пользователем» (нейтральная серая галочка, как high, но с иной иконкой — «рука», не «ИИ») — сигнализирует, что дальше это уже не ИИ-оценка, а данные пользователя, и не должно повторно помечаться как «требует проверки» при синхронизации с базой нутриентов.
- Кнопка «Подтвердить» после любой правки на короткое время (400мс) показывает состояние загрузки (спиннер внутри кнопки, не поверх экрана) → сменяется на чекмарк → переход в дневник с записью, добавленной сверху списка (свежая запись, короткая подсветка фона 1 секунда, затухающая).

### 5.3 Пересчёт нормы под тренировочный день

- Триггеры пересчёта: (а) автоматически при открытии приложения в новый день (ФТ-4.1 — по расписанию профиля), (б) вручную, если пользователь меняет отметку тренировочного дня в Настройках или через быстрый тоггл на главном экране (для нерегулярных тренировок, отличных от заданного расписания).
- Визуальная последовательность при (б) — ручном переключении дня прямо с главного экрана (быстрый тоггл рядом с пилюлей типа дня, иконка «изменить»):
  1. Пилюля типа дня плавно перекрашивается (crossfade 300мс) оранжевый↔синий, иконка меняется (пламя↔полумесяц) с лёгким scale-bounce.
  2. Кольца КБЖУ **не дёргаются мгновенно** — прогресс-дуги анимированно перетекают к новым целевым значениям (ease-out, 500мс), числа внутри тикают count-up/count-down синхронно с движением дуги — пользователь физически видит, что «углеводы выросли», а не просто увидел новую цифру.
  3. Белковое кольцо **не анимируется** (или анимируется минимально/невидимо) — визуально подтверждает ФТ-4.3: белок не меняется от смены типа дня, и пользователь должен буквально это заметить через отсутствие движения на фоне движения остальных колец.
  4. Короткий тост снизу: «Норма обновлена: +134 г углеводов на сегодня» — конкретное число, не общая фраза.

### 5.4 Автокоррекция нормы по весу (ФТ-7.3–7.4)

- Появление предложения корректировки — не модальное окно (не прерывает поток), а плашка, аккуратно «вдвигающаяся» сверху карточками экрана 7/главного экрана при следующем визите (slide-down, 300мс), с лёгкой haptic-вибрацией на мобильных, поддерживающих Vibration API.
- Принятие («Принять») — числа нормы на главном экране в этот момент проигрывают ту же count-up/count-down анимацию, что и при смене типа дня (5.3, п.2) — переиспользование одного языка анимации для «норма изменилась», независимо от причины изменения (день/вес) — консистентность паттерна.

## 6. Accessibility и touch-target минимумы

Обоснование критичности раздела для этого продукта конкретно: сценарии использования — «в зале потной рукой» и «на кухне с одной занятой рукой» (agent2 п.5.8, прямая параллель с эргономической проблемой MyPlate).

### 6.1 Touch targets

- Минимальный размер интерактивного элемента — **48×48px** (жёсткое требование, не рекомендация — прямое указание agent2 п.5.8, соответствует WCAG 2.5.5 и Material Design guideline).
- Минимальный отступ между соседними тач-таргетами — **8px**, чтобы избежать случайных нажатий влажными/потными пальцами после тренировки.
- Кнопка спуска затвора камеры (экран 3) и FAB ввода веса (экран 7) — увеличены до **64–72px**, поскольку это самые частые одноручные действия в сессии.
- Нижняя таб-навигация — зоны нажатия на всю высоту таба (64px), не только вокруг иконки — упрощает попадание на ходу/в движении.
- Основные CTA-кнопки («Подтвердить», «Добавить», «Принять/Отклонить») — высота **52px**, полная ширина контейнера на мобильном.

### 6.2 Зона большого пальца (thumb zone)

- Все основные действия (подтверждение блюда, спуск затвора, добавление спортпита, ответ на предложение корректировки) размещаются в нижней трети экрана — зоне, легко достижимой большим пальцем при одноручном хвате (прямое противодействие проблеме MyPlate, agent2 п.5.8).
- Второстепенные/редкие действия (переход в настройки, детальная аналитика уровня 3) — допустимо размещать в верхней части экрана, куда тянуться приходится реже.

### 6.3 Контраст и цветовое кодирование

- Текст: минимум **4.5:1** (обычный текст) и **3:1** (крупный текст ≥24px/`display`-токены) на фоне — проверено для обеих тем по палитре раздела 1.1.
- **Ни один статус не кодируется только цветом**: confidence (5.1) — цвет + иконка + текст при low; тип дня (2.2) — цвет + иконка + текст всегда; дельта веса (экран 7) — цвет + явный знак «+»/«−» в числе. Это обязательное требование для пользователей с нарушением цветовосприятия (учитывая, что оранжево-синяя пара день/тип и жёлто-зелёная пара confidence/успех потенциально проблемны при некоторых типах дальтонизма).
- Фокус-состояния полей ввода и кнопок — видимый outline (2px, брендовый акцент), не только изменение фона — обязательно для навигации с клавиатуры на десктопной версии веб-приложения.

### 6.4 Прочее

- Минимальный размер шрифта для текстовых полей ввода — 16px (см. 1.2) — предотвращает нежелательный авто-zoom в мобильных браузерах при фокусе, который иначе ломает layout.
- Все иконки-only кнопки (крестик удаления, карандаш редактирования, фонарик на сканере) — обязательный `aria-label` на русском для скринридеров, несмотря на визуальную самоочевидность иконки.
- Уведомления/тосты (тайминг ФТ-5.2–5.4) не должны быть единственным каналом критичной информации — дублируются постоянным видимым состоянием на главном экране (контекстный блок «Ближайшее», экран 2), на случай если пользователь отклонил push-разрешения браузера.
- Анимации (5.3, 5.4) должны уважать `prefers-reduced-motion`: при включённой настройке — count-up/count-down числа заменяются мгновенной сменой значения без движения дуг.
