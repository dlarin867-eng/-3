## 2026-08-22 (4)
**Сделано:**
- Объяснили механику разрыва hard link: Edit-инструмент не дописывает файл на месте, а атомарно подменяет его новым (защита от порчи при сбое) — путь в `.claude\agents\` начинает указывать на новый файл, путь в `агенты\...` — на старый. Так расходится содержимое.
- Пробовали настоящий фикс — заменить hard link на symlink (он переживает подмену файла, т.к. хранит путь, а не физический файл). **Не получилось:** `New-Item -ItemType SymbolicLink` требует прав администратора или включённого Developer Mode — ни того ни другого на этой машине нет. По пути ненадолго остались без копий в `агенты\...` (Remove-Item отработал, New-Item — нет) — сразу восстановили через hard link, проверили по хешу, ничего не потеряно (плюс всё это уже было в git).
- Спросили пользователя explicit: автоматизировать пересборку hook'ом, включить Developer Mode, или чинить вручную как раньше. **Решение: чинить вручную** — пересобирать hard link PowerShell'ом (`Remove-Item` + `New-Item -ItemType HardLink`) после каждой правки любого из 11 файлов агентов через Edit-инструмент.
**Дальше:** Ничего не меняли по существу (`Agent`-инструмент и отчёты.md из прошлой записи остались как есть) — эта запись фиксирует только диагностику и решение не менять механизм синхронизации.
**Заметки:** **Важно на будущее:** если снова нужно будет чинить hard link — НЕ пробовать `-ItemType SymbolicLink` на этой машине без прав/Developer Mode, сразу использовать `-ItemType HardLink`. Скрипт-заготовку в отдельном `.ps1`-файле лучше не использовать для кириллических путей через `powershell -File` — Windows PowerShell 5.1 читает `.ps1` без BOM в системной кодировке (не UTF-8), кириллица превращается в мусор («УРОК» → «РЈР РћРљ»); либо сохранять `.ps1` с BOM, либо (проще) выполнять команды напрямую через инструмент PowerShell, а не через файл.
