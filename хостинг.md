# Хостинг и инфраструктура — заметки к блоку 10

*Зафиксировано 22 августа 2026, по ходу попытки быстро развернуть MVP для теста.*

## Два принципиально разных варианта

**1. Managed-платформы (Vercel + Railway и подобные)**
- Быстро: одна команда — и работает, HTTPS/масштабирование из коробки.
- Отдельные аккаунты на каждый сервис, часто требуют карту после бесплатного лимита.
- Хорошо для быстрого теста «пощупать», не для постоянной эксплуатации без осознанного решения по деньгам.

**2. Свой сервер (VPS)** — DigitalOcean/Hetzner/Timeweb/Selectel и т.п.
- Сам ставишь Node.js, PostgreSQL, Nginx, HTTPS-сертификат (Let's Encrypt).
- Один платёж за всё, обычно дешевле в пересчёте на ресурсы, полный контроль.
- Вся эксплуатация (обновления безопасности, бэкапы, что делать при падении) — на тебе/qa-devops. Это не разовая настройка, а постоянная работа — собственно блок 10 задачника.

## Решение (важно, не забыть)

**У фаундера уже есть оплаченные облачные серверы (Timeweb и подобные) — для реального релиза продукта (блок 10) разворачивать нужно на них, а не заводить Railway/Vercel как постоянное решение.** Managed-платформы использовались только для быстрого одноразового теста.

## Статус попытки деплоя на Railway/Vercel (22 августа 2026)

- Аккаунты Vercel и Railway созданы и залогинены (CLI-токены сохранены на этой машине — можно переиспользовать).
- Backend (Fastify) + PostgreSQL задеплоены на Railway, миграции реально применились, сервер поднялся — в логах Railway подтверждено «Backend запущен: http://0.0.0.0:8080».
- **Проблема:** из этой рабочей среды (песочницы сессии Claude Code) не получилось достучаться ни до Postgres через публичный TCP-прокси Railway, ни до публичного HTTP-домена backend — таймауты на всех попытках (`curl`, PowerShell `Invoke-WebRequest`, сырой TCP-коннект через Node). При этом обычные сайты (Open Food Facts, npm registry, OAuth Vercel/Railway) из этой же среды отвечали нормально — похоже на специфическое сетевое ограничение именно для доменов Railway из этой песочницы, а не на проблему самого деплоя.
- Frontend на Vercel запустить ещё не успели (остановились на диагностике Railway).

## Итог (22 августа 2026, позже в тот же день)

Пользователь проверил `/health` backend напрямую из своего браузера — **реально ответил `{"status":"ok"}`**. Значит ограничение было только в рабочей среде этой сессии (её собственный сетевой доступ), не в самом деплое — backend полностью доступен и рабочий.
